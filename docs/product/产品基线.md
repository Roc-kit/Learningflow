# Learningflow 产品基线

更新日期：2026-09-12

本文件回答“Learningflow 要解决什么问题、服务谁、首版必须形成什么闭环”。具体语音/网页交互过程见 `真实学习流程.md`；完整技术设计见 `../architecture/系统架构.md`。

## 1. 问题定义

家庭个性化学习长期存在两个基础问题：

1. **学习数据太稀疏。** 学校往往只能给出总分或有限小分，家庭缺少连续、可解释的学习证据。
2. **知道错了不等于知道怎么教。** 错题本能记录错误，但很难持续验证前置知识、错因、提示效果、延迟保持和教学方法是否有效。

Learningflow 从家庭侧持续采集 Learning Evidence，把每天已经发生的学习活动转成可追踪的长期数据：

```text
学校作业 / 试卷
+ AI 练习
+ 文字和语音问答
+ 朗读 / 写作
+ 复习与延迟复测
        ↓
Continuous Learning Evidence
        ↓
Learner State + Teaching Reflection
```

## 2. 产品目标

围绕孩子每天真实发生的学习，让下面的循环可以持续运行，而不是只在某次聊天中存在：

```text
任务
→ 作答
→ 证据保存
→ 诊断
→ 教学
→ 针对性再练
→ 延迟复测
→ 状态更新
→ 下一次学习
```

同时形成第二条反馈链：

```text
教学动作
→ 当场表现
→ 延迟表现
→ 教学反思
→ 策略调整
→ 下一次教学继续验证
```

## 3. 三类使用者

| 使用者 | 主要入口 | 核心任务 |
| --- | --- | --- |
| 孩子 | ChatGPT App 为主；Learningflow Web 按需 | 听讲、问答、直接完成 AI 练习；需要图片、复杂交互、录音等专用采集时再进入 Web |
| 家长 | Learningflow 管理页 + 企业微信 | 登记/检查任务、处理例外、查看完成情况与长期进步 |
| 维护者 / Agent | 管理页、API、MCP | 导入资料、验证策略、维护系统、按需调用外部能力 |

登录账号与学生档案分开建模；未来可支持一个家长管理多个学生或多位监护人关联同一学生。

## 4. 首版必须覆盖

- 多学生 / 多账号基础模型，以及 Test / Real 严格隔离；
- 今日任务、作业监督、开始/暂停/提交/订正/完成；
- 作业拍照上传、压缩归档、OCR/多模态提取和人工修订；
- ChatGPT 内直接追加练习，并在可用时通过 Skill / MCP 保存结构化问题、作答、提示与结果；
- Learningflow Web 作为专用交互能力，支持图片、复杂题型、长文本、录音和其他 ChatGPT 对话不适合直接承载的输入；
- 判分、错因候选、少量诊断、针对性讲解与再练；
- 可解释的学习状态、到期复习和延迟复测；
- ChatGPT App 内文字/语音教学与 Assessment Skill 的连续衔接；当使用 Web 时再处理 Web 结果回到当前教学上下文的交接；
- 企业微信群 Webhook、逾期提醒、日报/周报；
- 教学反思与教学策略版本；
- HTTP API / MCP；
- 外部工具/内容能力的按需发现和使用经验记录。

## 5. 首版明确不做

- 自建完整实时语音老师；
- 全学段、全学科知识图谱；
- 同时实现多个学科；
- 完整学校管理 / 班级 / 教师 SaaS；
- 商业化、多租户计费等产品能力；
- 预建并长期维护豆包、元宝、微信、抖音、小红书等全平台连接器；
- 冷启动阶段同时引入 BKT、IRT、FSRS 等多套复杂学习模型；
- 为“看起来完整”而提前拆分微服务。

## 6. 三个不能混为一谈的维度

### 6.1 题目来源

例如：学校老师、教材/练习册、家长、AI 生成。

### 6.2 题型

例如：单选、多选、填空、匹配、排序、阅读、听力、写作、口语。

### 6.3 作答媒介

例如：ChatGPT 文字回答、ChatGPT 语音回答、纸笔照片、网页选择/输入、网页录音。

“练习册题”不是题型，“网页题”也不是知识点。三者分开，才能让 Evidence、评分和 UI 各自演进。

## 7. 三类状态也必须分开

| 状态 | 关注的问题 |
| --- | --- |
| 作业/任务状态 | 今天这件事做没做、是否逾期、是否需要订正 |
| 提交处理状态 | 图片/答案是否收到、是否识别、是否待确认、是否批改 |
| 学习证据/状态 | 是否独立、是否提示后完成、错因是否验证、是否延迟复测通过 |

上传一张照片只能证明“材料已提交”，不能自动证明“作业全部完成”；刚讲完答对也不能自动证明“稳定掌握”。

## 8. 学习状态的目标

首版不追求一个伪精确的 0–100 mastery 分数，而是采用可解释、可追溯的状态，例如：

```text
未接触
证据不足
练习中
基本掌握
稳定掌握
```

并同时展示：

- 证据量与证据类型；
- 最近独立验证时间；
- 是否存在活跃错因；
- 是否到期复习；
- 理解 / 独立应用 / 迁移 / 保持分别有什么证据。

## 9. 产品成功的首个判断标准

不是“后台模块是否齐全”，也不是“是否做出了完整练习网页”，而是孩子是否能真实完成：

```text
听懂当前问题
→ ChatGPT 在合适时机进入短验证
→ 直接用文字或语音回答
→ 系统在能力允许时保存可追踪的结构化 Learning Evidence
→ 根据答案继续追问或换一种讲法
```

只有当 ChatGPT 本身不适合承载当前输入或题型时，才调用 Learningflow Web。M0 先把这条 ChatGPT-first 链路跑顺，再增加完整作业、OCR、复习和报告能力。
