# 真实学习流程：ChatGPT 语音老师 + 网页练习本

基线来源：建仓前真实学习流程 v0.2。更新日期：2026-09-12。设备：iPhone、iPad、安卓手机、笔记本；当前套餐：ChatGPT Plus。

本轮先明确产品流程与交接方式。以下链接、工具和界面均为设计，尚未实现或做设备实测。

## 1. 三个使用场所

| 场所 | 孩子做什么 | 系统承担什么 |
|---|---|---|
| ChatGPT App | 听讲、追问、口头解释、讨论错因 | 依据当前教学材料与结果开展语音教学 |
| 纸面作业 | 完成学校作业与练习册 | 拍照归档、OCR、关联题号、判分与诊断 |
| 服务器作业网页 | 做 AI 追加题、提交答案、查看保存状态 | 呈现题型、收集结构化答案、保存与处理 |

日常先用一个主要语音设备；网页可在笔记本或另一台平板打开。双设备方便看题和交接，独立测验时仍暂停讲解。单设备按“语音 → 作业网页 → 返回对话 → 语音”切换。

## 2. 接入能力与设计前提

OpenAI 开发文档目前说明，ChatGPT 网页端开发者模式向 Plus 等套餐开放，支持 MCP 的读写工具。因此可用现有 Plus 先验证服务器连接，不必先假定需要升级套餐。账号实际入口、权限与确认行为仍以实测为准。[ChatGPT Developer mode](https://developers.openai.com/api/docs/guides/developer-mode)

这份文档不能证明手机 App 的语音会话也支持全部 MCP 操作。先分别验证“网页文字工具调用”“结果进入当前教学上下文”“切回语音能继续讲解”；不能把某一种桌面语音能力直接套用到所有手机语音模式。

| 交接事项 | 优先路线 | 接入能力不足时的路线 |
|---|---|---|
| 课前取得作业/薄弱点 | 支持 MCP 的文字对话读取教学材料 | 从作业网页复制教学材料，粘贴到实际语音对话 |
| 将 GPT 出的题落成作业 | GPT 调用创建练习工具，服务器验证并保存，返回真实链接 | GPT 输出约定结构的题目包，由家长导入网页并验证保存 |
| 交卷后让 GPT 知道答案 | 在支持工具的文字对话按提交 ID 读取结果 | 网页复制含题目与作答的结果包，粘贴回实际教学对话 |
| 保存教学经过 | 可取得的工具调用记录、显式提交的复盘 | 复制简短复盘到服务器，标记其来源和不完整性 |

网页提交不会自行向任意 ChatGPT 对话推送消息；打开同一账号也不等于运行中的语音立即知道新数据。如果手机无法给带开发工具的对话启用语音，可用普通语音对话接收教学材料及结果包，不强求它与工具对话完全相同。

## 3. 推演一次晚间学习

### 第一步：形成今日清单

例如今天有学校英语作业一页、课外练习册两题，以及一项到期短复习。

家长或孩子上传作业要求/页面，确认学科、页码、题号、截止时间。纸面教材保留版本和原图；老师布置的作业在纸上照常完成。AI 追加题是新的练习任务，关联触发它的旧题或薄弱点。

无需为了登记任务就预先 OCR 整本练习册，也无需孩子把纸面题目重抄到网页。

### 第二步：纸面作业完成后提交照片

系统先显示“照片已收到”，再依次显示识别、待核对、批改进度。模糊、漏页或题号对应错误只要求确认相关区域。

假设系统识别到：`Does Tom goes to school?`。它保存原图、识别文本和可能的错误，暂不直接认定孩子已经形成某个错误概念。

### 第三步：把本次教学材料交给 ChatGPT

教学材料包括：当前问题、学生原答案、待验证错因、相关前置知识、近期独立作答表现、教材范围，以及本轮目标。它带学生范围、学习会话 ID、材料版本和来源。

孩子进入语音后，GPT 可以问：“这句话在问谁？为什么选 Does？”短口头追问可直接在语音中完成；需要比较多题表现时再进入网页。

### 第四步：GPT 设计短诊断练习

示例三题：

1. 单选：哪个主语属于第三人称单数？`I / They / Tom`。
2. 填空：`___ Tom like cats?`。
3. 填空：`Does Tom ___ (like) cats?`。

三题分别观察前置概念、助动词选择、助动词后动词形式。它们用于决定下一步讲什么，不能凭三道题就确定长期掌握。

如果这些题已经被 GPT 讲过或透露过答案，它们属于引导练习；之后另外生成未见过的题验证独立作答。

### 第五步：服务器生成实际可做的练习链接

```text
GPT 生成题目内容与目标
→ 创建练习工具接收结构化题目包
→ 服务器校验题型、答案、关联知识点和学生范围
→ 保存固定版本的题目与本次练习
→ 返回 practice_id 和真实作业链接
→ GPT 在对话中展示“打开这 3 道题”
```

页面由可复用题型组件渲染。HTML 是孩子看到的界面；题干、选项、答案、评分标准和学生作答是独立的数据。标准答案与评分逻辑留在服务端，测验时不随页面数据一起暴露。

链接指向本次具体练习，打开即到题目；已登录设备可在“进行中的练习”找到同一份作业。双设备之间用此列表或扫码打开，不能依赖某种系统专有剪贴板功能。练习 ID 不是授权凭证，服务端仍检查学生访问范围。

### 第六步：网页做题与交卷

选择题点击选项、填空题在对应空位输入，答案逐题保存。网页区分“草稿已保存”“已交卷”“正在批改”“结果可用”。刷新页面能恢复未交卷答案。

交卷生成 submission_id。交卷后的订正另记一次尝试，原答案保留；服务器先保存原始输入，再做大小写、空白等按题目规则的归一化判分。

### 第七步：结果回到教学

返回教学的数据至少包含：本次题目、学生答案、判分、提示和作答模式、练习/提交 ID、版本。只告诉 GPT“得了 67 分”不足以支持下一步教学。

例如：前两题正确、第三题填 `likes`。GPT 可以据此把追问集中在 does 后的动词形式，并继续验证，减少对已经有证据的前置概念重复讲解。

先确保结果进入实际教学对话，再继续语音。未取到结果时老师应明确等待或索取结果，不能凭孩子一句“做完了”编造批改。

### 第八步：收尾与后续跟踪

分别记录校内任务完成、练习提交、教学发生、错因是否得到支持、独立练习表现。安排另一时间的短复测，并把当天任务完成情况合并成家长报告。

语音教学的复盘如果只有摘要，就保存摘要及其依据。ChatGPT App 的逐轮原始音频、提示时机或转写不假定自动写入服务器；需要精确评估的朗读题单独通过网页录音采集。

## 4. 来源、题型、作答方式分别建模

| 维度 | 示例 |
|---|---|
| 题目来源 | 校内老师、课外练习册、AI 生成 |
| 题型 | 单选、多选、填空、匹配、排序、阅读、写作、听力、口语 |
| 作答方式 | 纸笔拍照、网页选择/输入、网页录音 |

同一份学校作业可包含多种题型、不同作答方式。阅读和听力通常是共享一段材料、下面包含多道子题，因此模型需要区分“材料”“子题”“答案位置”。

| 题型/输入 | 保存的答案结构 |
|---|---|
| 单选/多选 | 选项 ID / ID 列表 |
| 填空 | 每个空位 ID 对应的原始输入 |
| 匹配 | 左右元素 ID 的配对 |
| 排序 | 元素 ID 的有序列表 |
| 阅读/听力 | 共享材料 ID + 各子题答案 |
| 改错/写作 | 原始文本、修改版本；按题型记录改动位置 |
| 口语/朗读 | 录音文件 + 目标材料 + 转写版本 |
| 纸笔作业 | 原图区域 + 识别答案 + 识别修订与确认状态 |

网页答案直接以结构化数据交给程序和模型。客观题优先使用规则判分，开放题结合评分标准交给模型；不必先截网页图再让 AI 识别答案。

## 5. HTML 链接与对话内做题的选择

首期建议外部响应式作业网页，手机、平板、笔记本共用。这使纸面上传、题型交互、录音、草稿恢复和跨设备访问能独立验证。

对话内做题也有可行方向：官方 MCP UI 文档支持在 ChatGPT 对话旁展示交互组件，并由组件调用工具。后续可把同一套题型组件包装成内嵌练习卡；具体账号、手机端、语音状态下的可用性分别验证。[MCP 交互界面文档](https://developers.openai.com/plugins/build/chatgpt-ui)

普通聊天中输出一段 HTML 文本不会自动获得完整作业系统的身份、保存、判分与回传能力。核心交付是题目和答案服务，外部网页与内嵌卡片是它的不同入口。

## 6. 先验证的最小闭环

验证内容只需一处英语错误、三道网页题和一次语音讲解：

1. 用 Plus 在笔记本网页端验证读取教学材料、创建练习、读取结果三个 MCP 工具。
2. 把材料带到手机/iPad 的实际语音对话，确认它能准确讲当前问题；如果工具对话无法启用语音，验证复制交接。
3. 在另一个设备打开同一练习，答题、刷新、交卷，确认草稿和原答案完整保存。
4. 将结果交回语音教学，确认 GPT 引用的是这次具体作答，且不会看到未提交答案或拿错学生结果。
5. 用单设备重复切换，检查麦克风占用、页面恢复、结果交接和操作次数。

通过标准是这条路线能清楚、可重复地走完；若必须频繁由家长搬运材料，先把交接体验记为未达标，再决定是否推进内嵌界面或其他接入方式。
