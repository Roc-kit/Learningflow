# 真实学习流程：ChatGPT 主教学入口 + Learningflow 能力扩展

基线来源：建仓前真实学习流程 v0.2。更新日期：2026-09-12。设备：iPhone、iPad、安卓手机、笔记本；当前套餐：ChatGPT Plus。

本轮先明确产品流程与交接方式。以下链接、工具和界面均为设计，尚未实现或做设备实测。

## 1. 三个使用场所

| 场所 | 孩子做什么 | 系统承担什么 |
|---|---|---|
| ChatGPT App | 听讲、追问、直接做题、文字/语音回答、讨论错因 | 作为默认教学与练习界面，依据当前材料、长期上下文和工具结果持续教学 |
| 纸面作业 | 完成学校作业与练习册 | 拍照归档、OCR、关联题号、判分与诊断 |
| Learningflow Web | 只在需要图片、复杂交互、长文本、录音或受控采集时进入 | 提供 ChatGPT 不适合直接承载的专用输入与结构化交互 |

日常默认不切换界面：ChatGPT 直接讲、直接问、孩子直接回答。只有当前活动确实需要专用 UI 时，才由 Skill / 工具引导打开 Learningflow Web，完成后把结果返回当前教学上下文。

## 2. 接入能力与设计前提

OpenAI 开发文档目前说明，ChatGPT 网页端开发者模式向 Plus 等套餐开放，支持 MCP 的读写工具。因此可用现有 Plus 先验证服务器连接，不必先假定需要升级套餐。账号实际入口、权限与确认行为仍以实测为准。[ChatGPT Developer mode](https://developers.openai.com/api/docs/guides/developer-mode)

这份文档不能证明手机 App 的语音会话也支持全部 MCP 操作。先分别验证“网页文字工具调用”“结果进入当前教学上下文”“切回语音能继续讲解”；不能把某一种桌面语音能力直接套用到所有手机语音模式。

| 交接事项 | 优先路线 | 接入能力不足时的路线 |
|---|---|---|
| 课前取得作业/薄弱点 | 支持 MCP 的 ChatGPT 对话读取必要教学材料 | 复制最小教学材料进入当前教学对话 |
| 进入短验证 | Assessment Skill 约束“一次一题、先答后评、记录辅助情况”，题目默认直接在 ChatGPT 中呈现 | 普通 ChatGPT 问答，结束后保存结构化摘要 |
| 保存作答 | Skill / MCP 将题目、学生回答、输入媒介、提示情况写入 Learningflow | 无工具能力时保存会话摘要，并明确证据较弱 |
| 需要专用 UI | Skill 判断当前题型需要图片、复杂交互、录音等，再创建 Web 活动 | 手动打开对应 Learningflow 页面 |
| 保存教学经过 | 可取得的工具调用记录、显式提交的复盘 | 复制简短复盘到服务器，标记其来源和不完整性 |

ChatGPT 是否能在语音状态直接调用所需 Skill / MCP 需要逐设备实测。能力不足时允许先在同一对话文字状态完成工具调用，再继续语音；如果当前客户端完全无法调用工具，则使用结构化摘要 fallback。Web 提交不会自行向任意 ChatGPT 对话推送消息，因此只有在确实使用 Web 时才需要额外交接。

## 3. 推演一次晚间学习

### 第一步：形成今日清单

例如今天有学校英语作业一页、课外练习册两题，以及一项到期短复习。

家长或孩子上传作业要求/页面，确认学科、页码、题号、截止时间。纸面教材保留版本和原图；老师布置的作业在纸上照常完成。AI 追加题是新的练习任务，关联触发它的旧题或薄弱点。

无需为了登记任务就预先 OCR 整本练习册，也无需孩子把纸面题目重抄到网页。

### 第二步：纸面作业完成后提交照片

系统先显示“照片已收到”，再依次显示识别、待核对、批改进度。模糊、漏页或题号对应错误只要求确认相关区域。

假设系统识别到：`Does Tom goes to school?`。它保存原图、识别文本和可能的错误，暂不直接认定孩子已经形成某个错误概念。

### 第三步：把本次教学材料交给 ChatGPT

教学材料包括：当前问题、学生原答案、待验证错因、相关前置知识、近期独立作答表现、教材范围，以及本轮目标。它带学生范围、学习会话 ID、材料版本和来源。

孩子进入语音后，GPT 可以问：“这句话在问谁？为什么选 Does？”短口头追问可直接在语音中完成；需要比较多题表现时再进入网页。

### 第四步：GPT 进入短诊断 / Assessment 流程

示例三题：

1. 单选：哪个主语属于第三人称单数？`I / They / Tom`。
2. 填空：`___ Tom like cats?`。
3. 填空：`Does Tom ___ (like) cats?`。

三题分别观察前置概念、助动词选择、助动词后动词形式。默认由 ChatGPT 一次问一道，孩子直接用文字或语音回答。它们用于决定下一步讲什么，不能凭三道题就确定长期掌握。

如果这些题已经被 GPT 讲过或透露过答案，它们属于引导练习；之后另外生成未见过的题验证独立作答。

### 第五步：Assessment Skill 约束流程并记录

```text
GPT 判断现在需要验证
→ Assessment Skill 明确验证目标
→ 一次呈现一道题
→ 等待孩子真实回答
→ 记录题目、回答、媒介、提示和必要评分
→ 决定继续问 / 追问 / 讲解 / 结束验证
```

Skill 负责教学流程约束，不保存长期事实；长期记录写入 Learningflow Server。对于普通口头问答或文本填空，不创建网页只是为了结构化。

如果当前题型确实需要图片标注、匹配/排序、较长写作、独立录音或其他专用采集，Skill 再调用 Learningflow Web。Web 是 Assessment 的一种执行表面，不是默认路径。

### 第六步：孩子直接回答，必要时才进入 Web

默认情况下，孩子直接在 ChatGPT 中回答。文字回答保存原文；语音回答如果只能取得转写，则保存转写及来源，不能冒充服务器直接采集的原始音频。

当使用 Web 时，页面继续按题型保存草稿和最终提交；提交后的订正另记一次尝试，原答案保留。Web 路径可以提供更强的结构化和采集可靠性，但不自动代表“完全独立”。

### 第七步：结果持续留在教学上下文

返回教学的数据至少包含：本次题目、学生答案、判分、提示和作答模式、练习/提交 ID、版本。只告诉 GPT“得了 67 分”不足以支持下一步教学。

例如：前两题正确、第三题填 `likes`。GPT 可以据此把追问集中在 does 后的动词形式，并继续验证，减少对已经有证据的前置概念重复讲解。

直接 ChatGPT 问答时，结果天然位于当前教学上下文；Learningflow 负责把其中值得长期保存的事实结构化。只有使用 Web 或后台任务时，才需要显式把结果重新取回当前教学上下文。未取到外部结果时老师不能凭孩子一句“做完了”编造批改。

### 第八步：收尾与后续跟踪

分别记录校内任务完成、练习提交、教学发生、错因是否得到支持、独立练习表现。安排另一时间的短复测，并把当天任务完成情况合并成家长报告。

语音教学的复盘如果只有摘要，就保存摘要及其依据。ChatGPT App 的逐轮原始音频、提示时机或转写不假定自动写入服务器；需要精确评估的朗读题单独通过网页录音采集。

## 4. 来源、题型、作答方式分别建模

| 维度 | 示例 |
|---|---|
| 题目来源 | 校内老师、课外练习册、AI 生成 |
| 题型 | 单选、多选、填空、匹配、排序、阅读、写作、听力、口语 |
| 作答方式 | ChatGPT 文字、ChatGPT 语音、纸笔拍照、网页选择/输入、网页录音 |

同一份学校作业可包含多种题型、不同作答方式。阅读和听力通常是共享一段材料、下面包含多道子题，因此模型需要区分“材料”“子题”“答案位置”。

| 题型/输入 | 保存的答案结构 |
|---|---|
| 单选/多选 | 选项 ID / ID 列表 |
| 填空 | 每个空位 ID 对应的原始输入 |
| 匹配 | 左右元素 ID 的配对 |
| 排序 | 元素 ID 的有序列表 |
| 阅读/听力 | 共享材料 ID + 各子题答案 |
| 改错/写作 | 原始文本、修改版本；按题型记录改动位置 |
| 口语/朗读 | 录音文件 + 目标材料 + 转写版本 |
| 纸笔作业 | 原图区域 + 识别答案 + 识别修订与确认状态 |

网页答案直接以结构化数据交给程序和模型。客观题优先使用规则判分，开放题结合评分标准交给模型；不必先截网页图再让 AI 识别答案。

## 5. 对话内做题与专用 Web 的选择

首期默认选择对话内做题，因为它对孩子最自然，也最充分利用 ChatGPT 已有的文字、语音、上下文和推理能力。

Learningflow Web 只负责 ChatGPT 本身不擅长的部分，例如作业照片、图片标注、拖拽/排序、长文本编辑、朗读录音、受控测验等。未来若 ChatGPT 的内嵌 UI 足以承载这些交互，同一套后端能力也可以嵌入 ChatGPT，而不坚持外部网页。

核心交付不是一个页面，而是 ChatGPT 可以调用的长期学习能力：上下文读取、Assessment 工作流、Evidence 保存、状态读取和后台任务。Web 与内嵌组件只是其中的专用交互表面。

## 6. 先验证的最小闭环

验证内容只需一处英语错误、三次直接作答和一次连续教学：

1. 在 ChatGPT 中读取最小教学材料并开始讲解。
2. 进入 Assessment 流程，一次问一道，共取得三次文字或语音作答。
3. 验证题目、原始回答、提示/辅助情况和评分能够以结构化记录保存，且 ChatGPT 能继续引用这三次具体作答。
4. 分别测试文字与语音；语音无法直接调用工具时，验证最小 fallback，不为此强制切网页。
5. 额外选择一个确实需要专用 UI 的题型验证 Web 调用，确认它是按需能力而不是主流程前提。

通过标准是 ChatGPT 能保持为孩子的单一主教学入口，而 Skill / MCP / Web 的加入减少家长操作、增强长期记录，不迫使孩子为普通问答频繁离开教学上下文。
