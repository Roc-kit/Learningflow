# M0 最小学习闭环设计

更新日期：2026-09-12

状态：Stage 0 实施基线。本文只定义 M0 所需的最小业务对象、状态机、HTTP / MCP Contract 和验收边界，不冻结完整 Learningflow 技术栈，也不提前实现 M1/M2 的学生模型、OCR、复习算法和知识图谱。

## 1. M0 只验证什么

M0 的产品问题不是“能不能生成题”，而是下面这条真实链路能不能稳定成立：

```text
ChatGPT 讲解 / 追问
→ 生成 3 道结构化网页题
→ 孩子打开 Learningflow 页面自行作答
→ 草稿可靠保存
→ 一次明确交卷
→ Learningflow 保存真实答案并生成结果包
→ ChatGPT 在同一教学上下文准确取得这次结果
→ 根据具体答案继续教学
```

验收重点：

1. 孩子不需要把三道题重新口述给 ChatGPT；
2. ChatGPT 取得的是服务器已经保存的本次具体答案，不是模型对之前聊天的猜测；
3. 页面刷新、切换设备或 ChatGPT 上下文短暂中断时，已经保存的答题事实不丢失；
4. 题目答案和评分标准不会在孩子作答前通过网页接口泄露；
5. “教过”“答过”“答对”“独立掌握”从第一天起不混成一个状态。

M0 成功后才进入 M1 的作业照片 / OCR / 任务体系，以及 M2 的 Learner State / Review。

## 2. 从开源项目吸收什么

本轮源码研究不选择母项目，也不直接拼装多个项目代码。只吸收已经被真实实现验证过的边界和模式。

| 参考项目 | M0 吸收的设计 | M0 不吸收 |
| --- | --- | --- |
| Tutor MCP | exposure 与 assessment evidence 分离；题目和 rubric 在作答前冻结；持久 Session / Attempt | BKT、FSRS、SaaS、多租户、OAuth 全套运行时 |
| DeepTutor | Pending Question 服务端持久化；答案 key 不进入 learner projection；`registered → awaiting_input → answered → graded/abandoned` 生命周期 | 整套 Agent Runtime、Mastery Path、知识库 |
| OpenLingo | 结构化 Exercise schema + 独立 Renderer；英语题型组件化 | SRS、完整课程系统、聊天记忆 |
| Aristotle | `taught ≠ mastered`；预教学错误不是 fail；题目 novelty 不能只换名字；会话恢复应依赖持久事实 | 其脚本和文件格式；当前研究时仓库未见明确 LICENSE，不复制代码 |
| LSL | Event/Evidence 与 Learner State Snapshot 分层；未来状态输出保持可映射 | 不把 LSL 当内部事实库，不在 M0 生成 mastery snapshot |

代码复用只从许可明确且确实必要的模块开始；当前 M0 优先自行实现很小的领域模型，而不是引入上述项目为依赖。

## 3. M0 的核心原则

### 3.1 服务端拥有题目事务

一道需要保存和判分的网页题不是聊天文本，而是服务器对象。

```text
模型提出题目
→ create_practice_set
→ 服务器校验并冻结 ExerciseRevision
→ 返回 practice_url
→ 浏览器只读取 learner-safe projection
```

作答开始后，不能在原 `ExerciseRevision` 上偷偷修改题干、选项、答案 key 或评分规则。需要改变题目时生成新的 revision / practice set。

### 3.2 草稿可以覆盖，交卷事实不可覆盖

孩子输入过程中的草稿不是学习证据，可以更新：

```text
draft answer A
→ draft answer B
→ draft answer C
```

点击“交卷”后，本次提交冻结：

```text
draft
→ submitted
```

之后是否已判分由 `AssessmentRevision` 表达，不再回写 Attempt 的事实状态。提交后不能把原答案改成“正确答案”。如果确实再次作答，应产生新的 Attempt，而不是覆盖旧 Attempt。

### 3.3 Exposure 不是 Assessment

例如：

```text
ChatGPT 已经解释 does 后用动词原形
```

只说明孩子接触过教学内容。它可以形成 `TeachingEvent`，但不能直接形成“会了”的 Evidence。

只有孩子真的提交了答案，才形成 Attempt。是否能支持未来的“独立掌握 / 延迟保持”判断，要由后续 Evidence Compiler 根据辅助情况、题目新颖度、时间间隔等决定。

M0 **不计算 mastery**。

### 3.4 Learner-facing projection 绝不包含答案 key

服务端可以保存：

```text
题目
选项
accepted answers
reference answer
grading mode
```

但孩子页面在交卷前只取得：

```text
题干
可见材料
选项
输入要求
```

答案、rubric、reference answer 属于 teacher/server projection。

### 3.5 页面没有提示，不等于证明完全独立

M0 网页本身不提供答案提示，因此可以可靠记录：

```text
ui_hints_used = 0
```

但系统不知道孩子是否同时问了家长、翻书或切回 ChatGPT，所以不能自动写：

```text
independent = true
```

M0 默认输出：

```text
external_assistance = unknown
independence = unverified
```

以后如果有受控独立复测流程，再产生更强的独立 Evidence。

## 4. 最小领域对象

M0 只增加七个业务概念，其中 `ResultPack` 是投影，不单独建表。

```text
Student
  │
  └── LearningSession
        │
        └── PracticeSet
              │
              ├── ExerciseRevision × 1..3
              │      │
              │      └── Attempt
              │             │
              │             └── AssessmentRevision?
              │
              └── ResultPack      # 读取投影，不是事实表

LearningSession
  └── TeachingEvent*              # 可选，只有明确发生才记录
```

### 4.1 Student

M0 只需要最少身份范围：

```text
id
display_name
data_mode        real | test
timezone
created_at
```

`real` 与 `test` 从第一天隔离。测试练习不能进入真实学生的结果查询。

完整 User / Guardian / Membership 权限模型放到 M1；M0 不用临时复杂 RBAC 代替真正需求。

### 4.2 LearningSession

表示一次 Learningflow 业务学习 episode，不等同于 ChatGPT 内部会话。

```text
id
student_id
status           open | closed
intent?          本次学习目标的简短文本
source           chatgpt | manual
external_context_ref?   可选，仅用于未来可验证的外部上下文引用
started_at
closed_at?
```

M0 创建 `PracticeSet` 时，如果没有传 `session_id`，服务端可以创建一个 `open` session，并将其 ID 返回。这样调用方不需要先完成一套会话初始化协议。

### 4.3 PracticeSet

一组本次要交给孩子做的网页题。M0 接受 1–3 题，正式验收固定使用 3 题。

```text
id
student_id
session_id
purpose          diagnostic | practice | review
title?
status           ready | in_progress | submitted | cancelled
access_token_hash
expires_at
created_by       chatgpt | parent | system
created_at
first_opened_at?
submitted_at?
cancelled_at?
submission_idempotency_key?
```

规则：

- `access_token` 是高熵随机秘密，只在创建时返回原文，数据库保存 hash；
- learner URL 的 token 只授权当前 PracticeSet，不授权学生历史数据；
- M0 默认链接短期有效，可先使用 24 小时；
- PracticeSet 一旦 `submitted`，不能回到 `in_progress`；
- 需要重做时创建新的 PracticeSet / Attempt，保留第一次提交。

### 4.4 ExerciseRevision

一道已经冻结的题目版本。

```text
id
practice_set_id
position
exercise_type
content_json         # learner 可见
grading_spec_json    # learner 不可见
learning_targets_json?  # M0 允许字符串标签，不建立完整 Concept 表
generator             # chatgpt | parent | system
schema_version
created_at
```

M0 不先创建完整 `Concept` / `CurriculumVersion` 表。`learning_targets_json` 只为后续映射保留少量目标标签，例如：

```json
["一般现在时", "does 后动词原形"]
```

它不是 Learner State key，也不能据此自动降低或提高任何掌握状态。

### 4.5 Attempt

一次真实作答事务。

```text
id
practice_set_id
exercise_revision_id
student_id
status             draft | submitted | abandoned
raw_answer_json
input_modality     web_choice | web_text
ui_hints_used      0      # M0 页面无提示
external_assistance unknown
independence       unverified
started_at?
last_saved_at?
submitted_at?
```

M0 页面每道题最多有一个活跃 draft。草稿可覆盖；提交后本次 `raw_answer_json` 冻结。

### 4.6 AssessmentRevision

判分是对 Attempt 的分析，不是 Attempt 本身。

```text
id
attempt_id
revision
status             evaluated | pending_review | superseded
method             deterministic | teacher_review | llm_review
is_correct?        true | false | null
score?             0..1 | null
result_json
grader_version
created_at
supersedes_id?
```

M0 优先使用 deterministic grader。无法可靠自动判定的 `short_text` 可以保持 `pending_review`，把孩子原答案交给 ChatGPT 教师继续判断；不要为了让结果“完整”强行猜分。

`llm_review` 字段为后续兼容保留，M0 不要求实现自动 LLM 判分流水线。

### 4.7 TeachingEvent

只有能够明确确认“教学动作发生了”时才记录。

```text
id
student_id
session_id
kind               instruction | explanation | hint | feedback
summary
related_exercise_revision_id?
related_attempt_id?
source             chatgpt | parent | system
provenance         tool_call | manual_summary
occurred_at
created_at
```

它只记录 exposure / teaching action，不直接修改 Learner State。

### 4.8 ResultPack

`ResultPack` 是从 PracticeSet、ExerciseRevision、Attempt、AssessmentRevision 临时组装的 teacher projection，不单独存一份重复事实。

这样后续修订 Assessment 时，重新读取即可获得当前有效结果，不会出现“表里改了、复制出来的结果包没改”的双重事实源。

## 5. M0 Exercise Contract

M0 先支持三种最小题型：

```text
multiple_choice
fill_blank
short_text
```

听力、匹配、拖拽、录音、口语评分、作文等放到后续增量，不在 M0 一次性建设。

### 5.1 Multiple Choice

模型提交给服务器：

```json
{
  "type": "multiple_choice",
  "prompt": "Choose the correct sentence.",
  "options": [
    {"id": "A", "text": "Does Tom likes apples?"},
    {"id": "B", "text": "Does Tom like apples?"}
  ],
  "grading": {
    "kind": "choice_exact",
    "correct_option_id": "B",
    "explanation": "After does, use the base form like."
  }
}
```

learner projection 删除整个 `grading` 字段。

### 5.2 Fill Blank

```json
{
  "type": "fill_blank",
  "prompt": "Does Amy ___ basketball?",
  "grading": {
    "kind": "text_exact",
    "accepted_answers": ["play"],
    "normalization": ["trim", "casefold"]
  }
}
```

M0 normalization 只做少量明确规则，不做模糊语义匹配。

### 5.3 Short Text

```json
{
  "type": "short_text",
  "prompt": "Write one question with 'does'.",
  "constraints": {"max_chars": 200},
  "grading": {
    "kind": "teacher_review",
    "reference": "Check subject + does + base verb."
  }
}
```

这类题提交后可以显示“已保存，老师继续讲解”，而不是伪造一个确定分数。

## 6. 状态机

### 6.1 PracticeSet

```text
ready
  │ 第一次打开
  ▼
in_progress
  │ 明确交卷
  ▼
submitted

ready / in_progress
  └──────────────→ cancelled
```

`expired` 不必保存成永久状态，可由 `expires_at` 派生；如果后续需要审计再增加明确终态。

### 6.2 Attempt

```text
draft
  │ PracticeSet submit
  ▼
submitted

draft
  └─────────────→ abandoned
```

提交后的判分生命周期只存在于 `AssessmentRevision`：确定性题目可以立即 `evaluated`；无法可靠自动判定的题保持 `pending_review`。

M0 不允许：

```text
submitted → 修改 raw_answer
```

### 6.3 LearningSession

```text
open → closed
```

PracticeSet 已提交不要求 Session 立即关闭，因为 ChatGPT 还需要根据结果继续讲解。

## 7. HTTP Contract

HTTP 面向网页和普通程序；MCP 与 HTTP 调用同一应用服务，不通过“模型再请求自己的网页接口”绕一圈。

路径名称是 M0 基线，可在实现前做小幅调整，但语义边界不变。

### 7.1 Teacher / Agent 侧

```text
POST /api/practice-sets
GET  /api/practice-sets/{practice_set_id}/status
GET  /api/practice-sets/{practice_set_id}/result
POST /api/learning-sessions/{session_id}/teaching-events
```

`POST /api/practice-sets`：

```json
{
  "student_id": "stu_test_01",
  "session_id": null,
  "purpose": "practice",
  "title": "does 后用动词原形",
  "exercises": ["...1-3 structured exercises..."],
  "idempotency_key": "client generated uuid"
}
```

返回：

```json
{
  "practice_set_id": "ps_...",
  "session_id": "ls_...",
  "status": "ready",
  "practice_url": "https://.../p/<opaque-token>",
  "handoff_code": "LF-7K4P"
}
```

`handoff_code` 是方便家长/孩子跨设备识别本次练习的短码，不替代高熵授权 token；不能仅凭短码直接读取作答和学生历史。

### 7.2 Learner 侧

```text
GET  /api/learner/practice/{access_token}
PUT  /api/learner/practice/{access_token}/answers/{exercise_revision_id}
POST /api/learner/practice/{access_token}/submit
```

`PUT .../answers/{exercise_revision_id}` 只更新 draft：

```json
{
  "answer": {"text": "play"},
  "client_saved_at": "2026-09-12T20:31:10+08:00"
}
```

返回服务端 `saved_at` 和 Attempt ID，让页面明确显示“已保存”。M0 单设备优先，不实现复杂多人协同草稿合并；服务端保存事实时间为准。

`POST .../submit`：

```json
{
  "client_submission_id": "uuid"
}
```

同一个 `client_submission_id` 重试必须返回同一次提交结果，不重复生成 Evidence / Assessment。

提交事务至少保证：

```text
冻结所有当前 draft
→ 标记 Attempt submitted
→ 标记 PracticeSet submitted
→ 执行可确定的 deterministic grading
→ commit
```

如果 deterministic grading 某一题失败，原始提交仍必须保存；该题 Assessment 进入待处理，而不是整次交卷丢失。

## 8. MCP Contract

M0 只需要很少的工具。

### 8.1 `create_practice_set`

用途：ChatGPT 根据当前教学内容生成 1–3 道结构化题并取得网页链接。

输入：

```text
student_id
session_id?
purpose
title?
exercises[]
idempotency_key
```

输出：

```text
practice_set_id
session_id
practice_url
handoff_code
status
```

服务器必须验证题型 schema、选项唯一性、答案 key 是否指向存在选项、题量以及学生数据范围。

### 8.2 `get_practice_status`

用途：教学上下文只想知道孩子是否做完，不需要提前读取作答。

返回：

```text
ready | in_progress | submitted | cancelled
answered_count
total_count
submitted_at?
```

M0 默认不在 `in_progress` 阶段向教师模型暴露实时草稿答案，减少“老师根据半截输入提前提示答案”导致的证据污染。

### 8.3 `get_practice_result`

只有提交后返回完整 ResultPack。

建议结构：

```json
{
  "schema_version": "m0.result.v1",
  "practice_set_id": "ps_...",
  "session_id": "ls_...",
  "student_id": "stu_...",
  "purpose": "practice",
  "submitted_at": "...",
  "summary": {
    "total": 3,
    "answered": 3,
    "correct": 2,
    "pending_review": 1
  },
  "items": [
    {
      "position": 1,
      "exercise_revision_id": "ex_...",
      "type": "fill_blank",
      "prompt": "Does Amy ___ basketball?",
      "learner_answer": {"text": "plays"},
      "assessment": {
        "status": "evaluated",
        "is_correct": false,
        "reference_answer": "play"
      },
      "evidence_context": {
        "input_modality": "web_text",
        "ui_hints_used": 0,
        "external_assistance": "unknown",
        "independence": "unverified",
        "delayed_probe": false
      }
    }
  ]
}
```

这个结果包必须包含孩子的**原始具体答案**，不能只返回“2/3 正确”。

### 8.4 `record_teaching_event`

可选工具。ChatGPT 确实完成讲解、提示或反馈后调用：

```text
session_id
kind
summary
related_attempt_id?
related_exercise_revision_id?
occurred_at?
idempotency_key
```

它记录教学发生，不产生 mastery 更新。

### 8.5 M0 明确不提供的 MCP 写工具

```text
set_mastery
mark_concept_mastered
resolve_misconception_without_evidence
submit_attempt_as_student
arbitrary_sql
```

网页直接采集的孩子答案只能由 learner HTTP 边界写入。未来确需 Agent 代录时必须使用不同 source/provenance，不能冒充网页原始作答。

## 9. 同一 ChatGPT 上下文的交接

M0 同时支持自动和 fallback 两条路线。

### 9.1 自动路线

```text
ChatGPT
→ create_practice_set
→ 告诉孩子打开 practice_url
→ 孩子交卷
→ ChatGPT 调 get_practice_status
→ submitted 后调 get_practice_result
→ 根据 items[].learner_answer 继续讲
```

这条路线需要实测 ChatGPT 当前文字 / 语音入口对远程 MCP 的真实支持和工具调用稳定性，不能只根据文档假定移动端语音一定可用。

### 9.2 Fallback 路线

结果页同时提供：

```text
复制“给 ChatGPT 的结果”
```

复制内容由 ResultPack 确定性生成，例如：

```text
Learningflow 练习 LF-7K4P 已提交
1. Does Amy ___ basketball?
   孩子回答：plays
   参考答案：play
   结果：错误
2. ...
3. ...
```

它只是 ResultPack 的文本渲染，不另存一份学习事实。

这样即使语音入口暂时不能直接调用 MCP，也能验证“网页做题 → 真实结果回到原聊天”的产品体验。

## 10. M0 不做 Learner State

M0 提交后允许回答：这次出了什么题、孩子具体答了什么、服务器确定判对/错了哪些、哪些题还需要老师判断、页面有没有给提示、教学动作是否明确记录过。

M0 不回答：知识点掌握百分比、未来遗忘概率、错因是否已经确认、是否稳定掌握、下一次必须何时复习。

这些需要更多纵向 Evidence，放到后续 State Compiler。

未来建议保持：

```text
Attempt / Assessment / TeachingEvent   # facts + versioned judgments
              ↓
        Evidence Compiler
              ↓
         LearnerState
              ↓
   LSL-compatible projection?
```

LSL 只作为未来互操作投影候选，不成为内部数据库格式。

## 11. M0 最小 UI

孩子页面只需要标题/简短说明、题目 1–3、草稿保存状态和交卷按钮。交卷后显示“已提交”“3/3 已保存”和“复制给 ChatGPT”。

M0 不需要：

- Dashboard；
- 知识图谱；
- 学习曲线；
- 错题本页面；
- 家长权限中心；
- 复杂动画；
- AI 聊天窗口；
- 多栏自适应工作台。

网页的职责是“可靠作答”，不是复制 ChatGPT。

## 12. M0 代表性测试

### 12.1 事实与安全

1. learner GET 响应中不存在答案 key、accepted answers、reference answer；
2. 刷新后 draft 恢复；
3. 交卷后 `raw_answer_json` 无法被 learner API 修改；
4. 同一 `client_submission_id` 连续提交两次只产生一次最终提交；
5. PracticeSet A 的 access token 不能读取 PracticeSet B；
6. test Student 的 PracticeSet 不能通过 real Student 查询路径取得。

### 12.2 教学证据

7. `record_teaching_event` 后不会自动产生 Assessment 或 LearnerState；
8. 一道题没有作答时结果明确为 unanswered，不自动记错；
9. `short_text` 无确定 grader 时保持 `pending_review`，不猜 is_correct；
10. 页面没有提示时只证明 `ui_hints_used=0`，结果包仍显示 `independence=unverified`。

### 12.3 真实交接

11. ChatGPT 创建 3 道题后能得到可在手机/平板打开的 URL；
12. 孩子交卷后，另一个设备上的教学上下文能取得同一个 ResultPack；
13. ResultPack 包含每题原始答案，不只有总分；
14. MCP 不可用时，从结果页复制 fallback 文本仍能让原聊天准确继续讲解。

## 13. M0 完成标准

M0 不以“表建完了”作为完成，而以一条真实端到端录像/操作记录能够证明下面流程为准：

```text
1. 在 ChatGPT 中讲一个四年级英语知识点
2. 创建 3 道 Learningflow 网页题
3. 孩子在真实设备打开链接并作答
4. 中途刷新一次，草稿仍在
5. 点击交卷
6. ChatGPT 取得三道题的具体原始答案
7. ChatGPT 根据其中至少一道错误继续追问 / 讲解
8. 整个过程中不需要家长手工重新录入孩子答案
```

如果第 6 步只能靠复制 fallback 完成，M0 仍可判定产品链路基本成立，但必须记录“自动 MCP 交接未通过”，继续作为 Stage 0 集成问题；不能用 fallback 冒充自动工具链已验证。

## 14. M0 之后再做什么

M0 通过后再根据真实使用结果决定：

```text
M1
→ Task / Homework Submission
→ 图片压缩与 MediaAsset
→ OCR / ExtractionRevision
→ User / Guardian / Membership
→ 完整 Test / Real 权限边界

M2
→ Concept / Curriculum Mapping
→ EvidenceLink
→ Diagnosis / Misconception
→ LearnerState Compiler
→ ReviewItem
→ 英语 Subject Pack
```

这保证 M0 的每个对象都能自然升级，但不会为了未来对象提前把当前原型做成完整平台。
