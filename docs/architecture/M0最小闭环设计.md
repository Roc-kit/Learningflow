# M0 最小学习闭环设计

更新日期：2026-09-12

状态：Stage 0 实施基线。

M0 的核心原则是 **ChatGPT-first**：孩子默认留在 ChatGPT 中完成教学、出题和作答；Learningflow、Skill、MCP、Web 和后台任务都只用于增强 ChatGPT，而不是建立一套平行的主教学系统。

## 1. M0 只验证什么

M0 验证下面这条最短真实链路：

```text
ChatGPT 讲解 / 追问
→ 判断现在需要验证
→ Assessment Skill 进入短验证流程
→ ChatGPT 一次问一道题
→ 孩子直接用文字或语音回答
→ Learningflow 在能力允许时保存结构化 Learning Evidence
→ ChatGPT 根据这次具体回答继续教学
```

正式验收使用 3 次作答，但“3”只是固定测试样例，不是产品规则。

M0 成功的关键不是“做出练习网页”，而是：

1. 孩子不需要为了普通问答离开 ChatGPT；
2. 出题后先等孩子回答，不能让模型自己把问答流程走完；
3. ChatGPT 能根据孩子这次真实回答继续教学；
4. 值得长期保存的题目、回答、提示和评价能形成结构化记录；
5. 文字与语音都能进入同一教学流程；
6. 当 ChatGPT 不适合承载某种输入时，才调用专用 Web；
7. “教过”“答过”“答对”“独立掌握”仍然保持不同含义。

M0 不验证 Learner State、复习算法、OCR、完整课程模型或复杂知识图谱。

## 2. 产品角色重新划分

### 2.1 ChatGPT：主教学运行界面

ChatGPT 负责：

```text
理解当前问题
讲解
追问
生成题目
听取/读取回答
形成教学判断
决定下一步教学动作
```

对孩子而言，ChatGPT 是默认入口。

文字和语音只是不同输入媒介，不拆成两套教学流程。

### 2.2 Assessment Skill：教学流程约束

Skill 不保存长期状态，也不代替 ChatGPT 推理。

它负责在“要验证孩子是否理解”时给 ChatGPT 一套可重复的操作纪律，例如：

```text
一次只问一道题
→ 等待孩子回答
→ 区分提示前 / 提示后回答
→ 不提前泄露答案
→ 必要时追问
→ 保存本次结果
→ 决定继续验证 / 回到讲解
```

Skill 的价值是把普通聊天变成比较稳定的教学流程，而不是构造一个新的 Agent。

### 2.3 Learningflow Server / MCP：长期事实与业务能力

Server / MCP 负责 ChatGPT 会话本身不适合长期承担的部分：

```text
学生范围
任务与材料
题目/回答事实
Evidence
历史状态
复习计划
教学反思
后台调度
通知
```

核心原则：

> Skill 决定怎么走教学流程；Server 保存真实发生了什么。

### 2.4 Learningflow Web：按需专用交互

Web 不是默认练习入口。

只有 ChatGPT 本身不适合当前活动时才调用，例如：

- 作业照片上传；
- 图片标注；
- 匹配 / 排序 / 拖拽；
- 多空位复杂表单；
- 长作文编辑；
- 需要长期保存的朗读录音；
- 需要更受控环境的独立测验；
- 未来其他专用视觉交互。

如果未来 ChatGPT 内嵌 UI 已经足够完成这些任务，同一能力可以迁入 ChatGPT，不坚持外部网页。

## 3. M0 的三种作答路径

### 3.1 默认：ChatGPT 文字

```text
GPT：Does Tom ___ (like) cats?
孩子：likes
GPT：读取原回答
→ 保存/评价
→ 继续追问或讲解
```

这是 M0 最可靠、最先验证的路径。

### 3.2 默认：ChatGPT 语音

流程与文字一致：

```text
GPT 语音出题
→ 孩子口头回答
→ GPT 继续教学
```

长期记录时需要区分服务器究竟取得了什么：

```text
原始音频        # 只有确实取得时才记录
官方/客户端转写 # 如果可取得
模型理解后的文本
会话摘要
```

如果 Learningflow 只能取得摘要或转写，就如实记录来源，不能把它当成服务器直接采集的原始音频。

### 3.3 可选：专用 Web

只有当前题型或采集要求需要时：

```text
Assessment Skill
→ 判断需要 specialized_ui
→ 创建 Learningflow Activity
→ 孩子完成
→ Server 保存结果
→ ChatGPT 读取结果
→ 回到教学
```

这条路径需要额外交接，因此不是普通题的默认选择。

## 4. Assessment Skill 的最小行为

M0 可以先把 Assessment Skill 理解成一份稳定教学协议，后续再根据 ChatGPT 实际可用的 Skill / Plugin / MCP 形态实现。

### 4.1 进入条件

适合进入 Assessment：

- 需要判断孩子是否理解刚讲过的规则；
- 需要区分两个可能错因；
- 需要一次无提示再尝试；
- 需要短暂复测；
- 孩子声称“会了”，需要验证。

不需要为了闲聊式追问或纯解释强制进入 Assessment。

### 4.2 一次一道题

Skill 默认执行：

```text
present question
→ stop
→ wait for learner response
```

不能在同一轮输出：

```text
题目
答案
解析
下一题
```

### 4.3 先保存回答，再解释

孩子作答以后，先识别本次实际回答，再决定：

```text
正确 → 简短确认 / 新变式
错误 → 判断是否需要追问
模糊 → 澄清
不会 → 进入教学
```

如果准备把这次作答当 Evidence，不能在保存前把孩子的原回答改写成标准答案。

### 4.4 区分练习和验证

至少区分：

```text
guided_practice
independent_check
delayed_check
transfer_check
```

M0 不据此计算 mastery，只把类型保存下来供以后重算。

### 4.5 提示要进入记录

如果 ChatGPT 在回答前已经提供：

- 答案片段；
- 规则提示；
- 排除选项；
- 明显示范；

那么这次回答不能和完全无提示作答视为同强度 Evidence。

M0 不要求精确量化提示强度，但至少能记录：

```text
none
light
substantial
unknown
```

## 5. M0 最小事实模型

M0 不冻结完整数据库，只要求未来实现能够保存以下事实。

```text
Student
  └── LearningSession
        ├── TeachingEvent*
        └── AssessmentRun*
              └── AssessmentItem*
                    ├── LearnerResponse*
                    └── AssessmentRevision*
```

### 5.1 LearningSession

一次长期学习系统可识别的 episode，不等于 ChatGPT 内部 conversation id。

建议最少字段：

```text
id
student_id
source                 chatgpt | manual | web
intent?
started_at
ended_at?
```

ChatGPT conversation id 如果未来能可靠取得，可以作为外部引用保存，但不能成为 Learningflow 主键。

### 5.2 TeachingEvent

只说明教学动作发生过：

```text
explanation
example
hint
correction
prompt
```

TeachingEvent **不是掌握证据**。

### 5.3 AssessmentRun

表示一次短验证过程，例如“检查 does 后是否使用动词原形”。

```text
id
session_id
purpose
mode              guided_practice | independent_check | delayed_check | transfer_check
surface           chatgpt_text | chatgpt_voice | web
started_at
ended_at?
```

### 5.4 AssessmentItem

表示实际问给孩子的一道题。

```text
id
assessment_run_id
sequence
prompt
question_type?
expected_answer?      # 仅 teacher/server 侧
rubric?
created_at
```

如果题目在孩子回答前被实质修改，应产生新的 item/revision，而不是覆盖原题。

### 5.5 LearnerResponse

这是 M0 最重要的事实之一。

```text
id
assessment_item_id
raw_answer
input_modality       text | voice | web | other
source_quality       direct | transcript | summary
assistance_level     none | light | substantial | unknown
occurred_at?
received_at
```

语音情况下，`raw_answer` 指系统实际取得的文本表示；若并非原始音频直接转写，要由 `source_quality` 说明。

一次纠正后的重新回答产生新的 `LearnerResponse`，不覆盖第一次错误回答。

### 5.6 AssessmentRevision

评价与原回答分开保存：

```text
response_id
result               correct | incorrect | partial | unclear | pending_review
normalized_answer?
reason?
evaluation_method    deterministic | llm | human
created_at
```

M0 不从这里直接写 `mastery=90%`。

## 6. M0 MCP / Tool Contract

最终工具名可以在实现时调整。M0 只需要很窄的能力面。

### 6.1 读取教学上下文

```text
get_learning_context(student_id, focus?)
```

只返回当前教学真正需要的上下文，例如：

- 当前任务；
- 最近错误；
- 最近一次相关回答；
- 已知待验证点；
- 教材范围。

不要把整个历史档案无选择塞进 ChatGPT。

### 6.2 开始短验证

```text
start_assessment(student_id, purpose, mode)
```

返回 `assessment_run_id`。

如果 M0 早期工具调用不方便，也允许 Skill 先在当前对话中完成问答，结束时再一次性写入结构化记录。

### 6.3 记录一道题

```text
record_assessment_item(
  assessment_run_id,
  prompt,
  question_type?,
  expected_answer?,
  rubric?
)
```

如果题目只用于即时教学且不值得长期记录，可以不调用。

### 6.4 记录孩子回答

```text
record_response(
  assessment_item_id,
  raw_answer,
  input_modality,
  source_quality,
  assistance_level
)
```

这是比“record mastery”更重要的写入口。

### 6.5 保存评价

```text
record_assessment(
  response_id,
  result,
  reason?,
  evaluation_method
)
```

M0 允许客观题由 ChatGPT 判断，但必须保留方法来源；后续可以重算。

### 6.6 结束短验证

```text
close_assessment(assessment_run_id)
```

返回一个面向 ChatGPT 的紧凑结果：

```text
本轮问了什么
孩子分别怎么答
哪些有提示
哪些正确 / 错误 / 不确定
建议继续讲哪里
```

“建议继续讲哪里”可以由 ChatGPT 自己根据原始结果推理，不要求 Server 预先做复杂 Pedagogical Engine。

## 7. Web 什么时候出现

Skill 在以下情况下可以选择 Web：

```text
需要上传照片
需要录音文件长期保存
需要复杂交互组件
需要一整页长文本编辑
需要更受控的独立测验
需要 ChatGPT 当前客户端做不到的输入能力
```

普通单选、口头问答、简单填空、造句，优先直接在 ChatGPT 中完成。

Web 返回结果仍然映射到同一事实模型：

```text
AssessmentRun.surface = web
LearnerResponse.input_modality = web
```

因此 Web 是一个 Adapter，不是另一套学习系统。

## 8. 语音的现实边界

M0 必须把“教学体验”和“长期证据质量”分开看。

孩子可以完全通过 ChatGPT 语音完成教学，这不要求 Learningflow 同时取得原始音频。

如果当前产品能力只能让 Learningflow 获得：

```text
GPT 生成的结构化摘要
```

则可以先记录：

```text
source_quality = summary
```

这种证据可以帮助下次教学，但强度低于服务器直接采集的回答。

后续需要精确发音分析或可复核音频时，再调用 Web 录音。

M0 不因为“拿不到 ChatGPT 原始语音文件”而放弃 ChatGPT-first 路线。

## 9. M0 不做 Learner State

M0 收集事实：

```text
问了什么
孩子怎么回答
通过什么媒介
之前是否提示
怎么评价
什么时候发生
```

M0 不急着输出：

```text
三单掌握度 82%
FSRS stability = 4.6
BKT p_mastery = 0.74
```

后续的 LearnerState Compiler 可以重新读取这些 Evidence，用更成熟规则计算当前状态。

## 10. M0 代表性验收

使用一处真实小学英语问题，例如：

```text
Does Tom goes to school?
```

完成以下测试：

1. ChatGPT 根据材料进行简短讲解；
2. 进入 Assessment Skill；
3. ChatGPT 一次只问一道，共 3 道；
4. 孩子至少用文字完成一次；
5. 孩子至少用语音完成一次；
6. ChatGPT 能引用每次具体回答继续教学；
7. 能取得工具能力时，题目/回答/提示/评价写入 Learningflow；
8. 工具能力不足时，fallback 不强迫孩子为普通题切换 Web；
9. 再选一个确实需要专用 UI 的活动，验证 Web 可以被按需调用并把结果返回 ChatGPT；
10. 整个流程中家长不需要反复搬运题目和答案。

## 11. M0 完成标准

满足以下条件即可进入 M1：

- ChatGPT 仍然是孩子的单一主教学入口；
- 文字和语音都可以自然完成“讲 → 问 → 答 → 继续讲”；
- Assessment Skill 能稳定约束一次一题和先答后评；
- Learningflow 能在可用能力范围内保存真实作答，而不是只保存模型总结出的 mastery；
- Web 证明可以按需提供专用交互，但普通问答不依赖它；
- Test / Real 数据不会混淆；
- 没有为了 M0 引入 BKT、FSRS、复杂知识图谱或完整 Agent Runtime。

## 12. M0 之后再做什么

M0 通过后，再按真实使用推进：

```text
M1
→ 作业任务
→ 照片 / OCR
→ 多学生 / Guardian
→ 最小课程映射

M2
→ Learner State
→ Misconception 验证
→ Review / 延迟复测
→ 更完整 Subject Pack

M3
→ 调度
→ 通知
→ 报告
→ 教学反思
```

后续每增加一个中间件都先问：

> 它是否让 ChatGPT 更了解孩子、更可靠地保存事实、或获得原本没有的能力？

如果只是复制 ChatGPT 已经做得足够好的聊天、语音、普通出题或解释能力，就不应该建设。
